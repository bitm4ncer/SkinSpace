Stand: 2026-10-13 · Auftrag: Deep-Research zu WMP9/WMP-Skin-Format, Tooling, Ökosystem, Herkunft von „Headspace“, Lizenzlage — als Grundlage für den Port nach VLC 3.0.x (skins2).
Methodik: `websearch`/`webfetch`, Quellen live abgerufen (die vollständige MS-Skin-Referenz ist unter `learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/` noch online; Archiv-Fallbacks waren nicht nötig). Lokale Fakten wurden mit 7-Zip am Original `research/original/Headspace.wmz` verifiziert.
Legende: **[VERIFIED]** = aus Primärquelle/mehrfach belegt gelesen · **[UNCERTAIN]** = unklar, widersprüchlich oder nur erschlossen.

## 0. Kernergebnisse

- Die komplette Microsoft-Skin-Doku (WMP7–12) ist **weiterhin online** (Legacy-Doku auf learn.microsoft.com). Alle Format-Details unten sind daraus belegt. **[VERIFIED]**
- **`.wmz` ist ein ZIP-Archiv** (offiziell von Microsoft so benannt; MS01-010 nannte es „zipped“). Keine MS-Quelle für „CAB“ gefunden. Unsere Datei: `Type = zip` (7-Zip). **[VERIFIED]**
- **Headspace ist ein WMP-7-Skin (2000)** — eines der sieben Skins, die mit WMP 7 ausgeliefert wurden — nicht WMP9 (WMP9 kam 2002). Die Datei-Timestamps (Jan–Jun 2000) und ©2000 stützen das. **[VERIFIED]** (mit einer abweichenden Fremdangabe „WMP9 (2001)“, siehe §4)
- **Skin-Unterstützung in WMP Legacy endet am 10.11.2026** auf Windows 11 24H2/25H2/26H2 (Warnhinweis auf allen MS-Doku-Seiten; Windows 10 nicht betroffen). Bis dahin funktioniert Skin Mode grundsätzlich noch — ein Test-Fehlschlag hat meist andere Ursachen (Blocked-File/Mark-of-the-Web, „Skin Chooser“-Workflow). **[VERIFIED]** (MS-Warnung) / Ursachenanalyse **[UNCERTAIN]**
- Modernes Ökosystem: **nullPlayer** (macOS, Open Source, GPL-3.0) ist der **einzige** gefundene saubere Open-Source-Interpreter für `.wmz` (WMP 7–12). Kein Windows-Port, kein zweiter `.wms`-Interpreter auffindbar. **[VERIFIED]** (Existenz) / „einziger“ **[UNCERTAIN]** (Negativbefund der Suche)

## 1. WMP-Skin-Format-Spezifikation (Hauptteil)

### 1.1 Dateien & Container

| Datei | Rolle | Doku |
|---|---|---|
| `*.wms` | Skin-Definition (XML, genau **eine** pro Skin; Elementname case-insensitive, Konvention GROSS) | [Skin Definition File](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/skin-definition-file) **[VERIFIED]** |
| `*.js` | JScript. Datei gleichen Namens wie die `.wms` wird **automatisch** geladen, zusätzlich per `scriptFile` | [VIEW.scriptFile](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/view-scriptfile) **[VERIFIED]** |
| Art | BMP, JPG, PNG, GIF (keine animierten GIFs); für Transparenz-JPGs gewarnt (lossy) | [Skin Files](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/skin-files), [mappingImage](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/buttongroup-mappingimage) **[VERIFIED]** |
| `*.wmz` | ZIP-Verteilung der Skin-Dateien | siehe unten **[VERIFIED]** |

**`.wmz`: ZIP oder CAB?** — Microsoft Support („File types supported by Windows Media Player“): *„A .wmz file is a compressed **Zip archive** that contains a Windows Media Player skin definition file and associated Jscript files and its supporting graphic files.“*; Security Bulletin MS01-010 (2001): *„WMZ is the default extension for a **zipped** Windows Media Player skins file“*; Archive Team (`justsolve.archiveteam.org/wiki/Windows_Media_Player_Skin_Package`): *„…actually ZIP archives.“* Lokaler Test (7-Zip an unserer Datei): `Type = zip`, 82 Einträge, Dateien liegen auf Root-Ebene (`headspace.wms`, `headspace.js`, 80 BMPs). **Fazit: ZIP, nicht CAB. Für die „CAB“-Behauptung fand sich in keiner geprüften MS- oder Fachquelle ein Beleg [UNCERTAIN, wohl Verwechslung].**
Quellen: [Microsoft Support](https://support.microsoft.com/en-us/windows/apps/windowsmediaplayer/file-types-supported-by-windows-media-player), [MS01-010](https://learn.microsoft.com/en-us/security-updates/securitybulletins/2001/ms01-010), [justsolve](http://justsolve.archiveteam.org/wiki/Windows_Media_Player_Skin_Package).

### 1.2 THEME (Wurzel)

Ein `<THEME>` pro Datei. Attribute: `id`, `author`, `copyright`, `title`, `version` (WMP-Version, design-time only), `authorVersion`, `currentViewID` (scriptbar). Methoden des Theme-Objekts (scriptbar als `theme.*`): `closeView`, `openView`, `openViewRelative`, `loadPreference`/`savePreference` (Registry-Prefs), `playSound`, `logString`, `showErrorDialog`, `openDialog`. Keine Event-Handler. **[VERIFIED]** ([THEME Element](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/theme-element))

Headspace: `theme id="headspace" author="Microsoft Corporation" copyright="©2000 Microsoft Corporation. All rights reserved."`.

### 1.3 VIEW (Fenster/UI eines Modus)

Ein THEME enthält ≥1 VIEW; jedes View hat eigenen Variablen-Scope. Referenz in Skripten: das aktuelle View über das **globale Attribut `view`**, andere über deren `id`.

Attribute (Auszug, vollständig in [VIEW Element](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/view-element)): `backgroundColor` (`"none"` möglich; Default VIEW=„white“, SUBVIEW=„none“ — `none` zeichnet keinen Hintergrund und ist ein Baustein für geformte Fenster), `backgroundImage`, `clippingColor`, `transparencyColor`, `backgroundTiled`, `backgroundImageHueShift/-Saturation`, `resizable`, `min/maxWidth/Height`, `resizeBackgroundImage`, `category`, `title`, `titleBar`, `scriptFile`, `timerInterval`, `focusObjectID`.

Methoden: `close()`, `minimize()`, `maximize()`, `restore()`, **`returnToMediaCenter()`** („Returns the user to the full mode of Windows Media Player“), `size(edge, value)`, `moveTo` etc. (ambient). Events: `onload`, `onclose`, `onerror`, `ontimer`. **[VERIFIED]** ([view-returntomediacenter](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/view-returntomediacenter), [view-minimize](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/view-minimize))

Headspace konkret:
- `<view backgroundColor="none" width="760" height="394" titleBar="false" resizable="false" scriptFile="headspace.js;res://wmploc.dll/RT_TEXT/#132;" onLoad="Init();" onClose="OnClose();">`
- `backgroundColor="none"` + geformte Subviews = einzigartige Fensterform (Kopf + abgerundete Ecken) statt Rechteck.
- `scriptFile` mit **zwei** Einträgen: eigenes `headspace.js` plus eine Win32-Ressourcen-URL (`res://wmploc.dll/RT_TEXT/#132`) — WMP zog also zusätzlichen Text/Script direkt aus seiner Lokalisierungs-DLL (WMP-Resources). Zweck im Detail **[UNCERTAIN]** (vermutlich lokalisierte Strings); für den Port irrelevant.
- `view.width = 549 / 760` wird zur Laufzeit in `headspace.js` gesetzt (Playlist öffnet/schließt) — d. h. **programmatisches Resize** trotz `resizable="false"` (das Attribut steuert User-Resize). **[VERIFIED an headspace.js]**

### 1.4 SUBVIEW (verschiebbare/hideable Teilbereiche)

Attribute (über VIEW geerbt): `backgroundColor`, `backgroundImage`, `backgroundTiled`, `clippingColor`, `transparencyColor`, `resizeBackgroundImage`, plus ambient `left/top/width/height/zIndex/visible/enabled/id/alphaBlend/...`. Event-Handler: nur `onendmove` und `onresize` (ambient). **[VERIFIED]** ([SUBVIEW Element](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/subview-element), [Ambient Attributes](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/ambient-attributes))

**Wichtige Mechanismen, die Headspace voll ausnutzt:**

- **Ambient `moveTo(newLeft, newTop, time_ms)`** — lineare Animation eines Elements (z. B. SUBVIEW) zu neuer Position; Gegenstück `slideTo` (nicht-linear), `moveSizeTo` (WMP11+). Danach feuert **`onendmove`**. Damit wird das Ein-/Ausfahren der beiden „Ohren“ (EQ links, Playlist rechts) animiert. **[VERIFIED]** ([moveTo](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/ambientattributes-moveto), [onendmove](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/onendmove))
- **`visible`** ist ambient und scriptbar (`sEqView.visible = true`) — Hide/Show als Alternative zur Bewegung.
- **Transparenz I: `transparencyColor`** — Farbwert, der im **Bild** (backgroundImage des Controls) als transparent behandelt wird (Farbkey der Bitmap). JPGs dafür ungeeignet. **[VERIFIED]** ([view-transparencycolor](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/view-transparencycolor))
- **Transparenz II: `clippingColor`** — Farbe im `clippingImage` bzw. `backgroundImage`, die **ausgeschnitten** wird: nicht sichtbar **und nicht klickbar** (Formmaske/Hit-Test). Default `Auto` = Pixel (0,0) ist die Clip-Farbe; beliebige IE-Farbwerte möglich. Nicht für PLAYLIST. **[VERIFIED]** ([clippingColor](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/ambientattributes-clippingcolor))
  → Headspace: `transparencyColor="#FF00FF"` (Magenta = „transparentes“ Farbfeld in BMPs) und `clippingColor="#FF0000"` (Kopfmaske) bzw. `clippingColor="#FFFFFF"` (Video-Bereich), teils kombiniert an einem Subview.

**Doku-Widerspruch (relevant für uns):** Die SUBVIEW-Seite behauptet, SUBVIEWs dürften **keine** SUBVIEWs enthalten — Headspace **verschachtelt** aber mehrfach (z. B. `sEqEar > sEqView > Rahmen-Subviews`). Das WMP-Original akzeptierte das klaglos. **[VERIFIED an Headspace; Doku vs. Praxis divergiert]**

Headspace: `#sEqEar` (EQ-Ohr, `onEndMove="EqOnEndMove();"`), `#sPlEar` (Playlist-Ohr, `onEndMove="PlOnEndMove();"`, verändert zusätzlich `view.width`), `#visDrop` (Visualizer-Dropdown, `onEndMove="VisDropOnEndMove();"`, fährt zwischen `y=33` und `y=59`).

### 1.5 Buttons & Button-Gruppen

- **`<BUTTON>`** (Einzelbutton): `image`, `hoverImage`, `downImage`, `disabledImage`, `hoverDownImage`, `upToolTip`, `downToolTip`, `cursor`, `sticky`, `tiled`, `transparencyColor`; dazu ambient `left/top/zIndex/visible/enabled/onClick/...`. Vorteil: Bilder zur Laufzeit austauschbar (`bEqHandle.image = "...";` — Headspace nutzt das für die Griff-Icons). **[VERIFIED]** ([BUTTON Element](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/button-element))
- **Predefined buttons** (Voll-Buttons mit eingebautem Verhalten): `PLAYBUTTON`, `PAUSEBUTTON`, `STOPBUTTON`, `NEXTBUTTON`, `PREVBUTTON`, `FFWDBUTTON`, `REWBUTTON`, `MUTEBUTTON`, `REPEATBUTTON`, `SHUFFLEBUTTON`, `MINIMIZEBUTTON`, `CLOSEBUTTON`, `RETURNBUTTON` („returns … to the media center“), `IMAGEBUTTON`. Headspace nutzt `PAUSEBUTTON` direkt. **[VERIFIED]**
- **`<BUTTONGROUP>` + `<BUTTONELEMENT>`**: Eine Gruppe teilt Zustandsbilder (`image`, `hoverImage`, `downImage`, `disabledImage`, `hoverDownImage`, `transparencyColor`, `cursor`) und eine **`mappingImage`** — eine Bilddatei in denselben Maßen wie `image`, in der jede klickbare Region mit einer **eindeutigen Füllfarbe** markiert ist. Jedes `<BUTTONELEMENT mappingColor="#RRGGBB">` aktiviert die Region dieser Farbe; **Klicks landen genau dort** (freie, nicht-rechteckige Hit-Zonen). Ungültige Farbe → Element wird „not activated“. **[VERIFIED]** ([mappingImage](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/buttongroup-mappingimage), [mappingColor](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/buttonelement-mappingcolor))
- **Predefined BUTTONELEMENTe** in Gruppen: `PREVELEMENT`→`player.controls.previous`, `PLAYELEMENT`→`play`, `PAUSEELEMENT`→`pause`, `STOPELEMENT`→`stop`, `NEXTELEMENT`→`next`, `FFWDELEMENT`, `REWELEMENT` — jeweils mit eingebautem `onclick`. **[VERIFIED]** ([BUTTONELEMENT Element](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/buttonelement-element))

Headspace konkret: zwei Gruppen (minimize/close mit `minimize_close_map.bmp`; Transport mit `play_controls_map.bmp`) + `pausebutton` (aus, wenn Pause nicht verfügbar: `visible="wmpenabled:player.controls.pause"`). Tooltip-Trick: versteckte `<text>`-Elemente (`enabled="false" visible="false"`) speichern die zwei Zustands-Tooltips (`toolTip` vs. `value`), beim Umschalten wird `upToolTip` des Buttons per Skript getauscht (`bEq.upToolTip = xEqTt.value;`).

### 1.6 SLIDER

Attribute: `backgroundImage`, `foregroundImage`, `thumbImage`, `thumbHoverImage`, `thumbDownImage`, `thumbDisabledImage`, `backgroundHoverImage`, `foregroundHoverImage`, `min`, `max`, `value`, `direction` (Bild-Layoutrichtung, z. B. horizontal/vertikal), `tiled` (Bilder kacheln statt strecken), `borderSize` („border size in pixels“, Randbereich für die Bildbehandlung — MS-Doku knapp), `slide` (Vordergrundbild gleitet über Hintergrund vs. wird beschnitten), `transparencyColor`, `toolTip`, Farbvarianten, **`useForegroundProgress`** + **`foregroundProgress`**. Events: `onDragBegin`, **`onDragEnd`**, `onPositionChange`. Zusätzlich generisch `value_onchange` (attribut_onchange-Muster). **[VERIFIED]** ([SLIDER Element](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/slider-element), [attribute_onchange](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/attribute-onchange))

**Zweiwege-Bindung** (MS-Pattern, exakt so in Headspace): `value="wmpprop:player.settings.balance"` (Player→UI) + `value_onchange="player.settings.balance=value;"` (UI→Player). Beim Seek: `onDragEnd="player.controls.currentposition=value;"` (erst am Ende der Drag-Geste übernehmen).

**Download-Progress-Feature:** `foregroundProgress` ist ein **Prozentwert (0–100) des Slider-Bereichs**; bei `useForegroundProgress="true"` wird ein zweiter Fortschritt gezeichnet, und **der Thumb ist auf den verfügbaren (bereits geladenen) Bereich beschränkt** — Seeken ist nur innerhalb des geladenen Teils möglich. MS' eigenes Beispiel ist fast identisch zum Headspace-Seek:

```c
<SLIDER id="seek" min="0" max="wmpprop:player.currentMedia.duration"
  value="wmpprop:player.controls.currentPosition"
  useForegroundProgress="true"
  foregroundProgress="wmpprop:player.network.downloadProgress"
  ondragend="player.controls.currentposition=value" />
```

**[VERIFIED]** ([foregroundProgress](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/slider-foregroundprogress), [useForegroundProgress](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/slider-useforegroundprogress), [downloadProgress](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/network-downloadprogress))

Headspace konkret: Seek `borderSize="9"`, `slide="false"`, Thumb-Set mit Hover/Down, `max="wmpprop:player.currentmedia.duration"`, `value="wmpprop:player.controls.currentposition"`, `foregroundProgress="wmpprop:player.network.downloadProgress"`. Balance- und Volume-Slider: `tiled="true"`, `borderSize="7"`, horizontal; 10 EQ-Slider vertikal (`tiled="true"`, `height="76"`, `min="-14" max="14"`).

### 1.7 TEXT

Attribute: `value` (scriptbar, `wmpprop`-fähig), `backgroundColor`, `foregroundColor`, `fontFace`, `fontSize`, `fontStyle` (z. B. `Underline`), `fontSmoothing`, `justification` (z. B. `Center`), `cursor` (z. B. `hand`), `toolTip`, `scrolling*`, `wordWrap`, Hover-/Disabled-Varianten, `textWidth`. Predefined: `CURRENTPOSITIONTEXT`, `DURATIONTEXT`, `TRACKNAMETEXT`, `STATUSTEXT`. Text ist klickbar (`onClick` ist ambient) — Headspace baut so den „reset“-Link. **[VERIFIED]** ([TEXT Element](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/text-element), [text-cursor](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/text-cursor))

Headspace konkret: nutzt **`fontType="Verdana"`** — `fontType` ist in der Doku **nicht** dokumentiert (dort heißt es `fontFace`); WMP akzeptierte es offenbar (evtl. stiller Alias/No-op). Für den Port: `fontFace` annehmen. **[UNCERTAIN]** (Details des Alias). Außerdem: Journal-Text `value="wmpprop:visEffects.currentPresetTitle"` (Viz-Presetname), Equalizer-Reset als unterstrichener Text mit `cursor="hand"`.

### 1.8 EQUALIZERSETTINGS

`<EQUALIZERSETTINGS id="eq" enable="true">` liefert das Script-Objekt `eq` (bzw. per id). Attribute: `gainLevel1`…`gainLevel10` (Band 1 = **31 Hz**-Band; „normally ranging from −20 to +20“, Default 0; `gainLevels(index)` als Alternative — **nicht** mit `wmpprop` nutzbar, daher die numbered Form), `bands` (read), `bypass`, `currentPreset`/`currentPresetTitle`, `presetCount`, `crossFade`/`crossFadeWindow`, `normalization*`, `speakerSize`, `splineTension`, `truBassLevel`, `wowLevel`, `enhancedAudio`. Methoden: `reset()`, `nextPreset()`, `previousPreset()`, `presetTitle()`. Events: `attribute_onchange`. **[VERIFIED]** ([EQUALIZERSETTINGS](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/equalizersettings-element), [gainLevel1](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/equalizersettings-gainlevel1), [gainLevels](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/equalizersettings-gainlevels))

Das `enable="true"`-Attribut ist in der Attributliste nicht dokumentiert (nur ambient-„enabled“ existiert) — vermutlich No-op/Legacy. **[UNCERTAIN]**

Headspace: 10 Sliders → `wmpprop:eq.gainLevelN` + `value_onchange="eq.gainLevelN=value;"`; „reset“-Text → `eq.reset();`.

### 1.9 PLAYLIST

Attribute u. a.: `columns` (Format `name=Name;Duration=Time` → Attributname=Spaltentitel), `columnsVisible`, `dropDownVisible` (+ `dropDownImage`, `dropDownBackgroundImage`, `dropDownToolTip`, `dropDownList`), `playlistItemsVisible`, `toolbarVisible`, `allowColumnSorting`, `allowItemEditing`, `checkboxesVisible`, `columnOrder`, `itemPlayingColor`, `itemSelected*`, `backgroundColor`, `foregroundColor`, Status-Texte. Methoden: `setColumnResizeMode(column, mode)` mit Modi `AutosizeHeader | AutosizeData | Fixed | Stretches`, außerdem `setColumnWidth`, `sortColumn`, `moveSelectedUp/Down`, `addSelectedToPlaylist`, `deleteSelected`, u. v. m. **[VERIFIED]** ([PLAYLIST Element](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/playlist-element), [setColumnResizeMode](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/playlist-setcolumnresizemode))

Headspace: `columns="name=Name;Duration=Time"`, `columnsVisible="false"`, `dropDownVisible="true"`, `playlistItemsVisible="true"`, dazu in `Init()`: `pl.setColumnResizeMode(0, "Stretches")` (Name-Spalte füllt Rest) und `(1, "AutoSizeData")` (Zeit-Spalte passt sich Daten an).

### 1.10 EFFECTS & VIDEO

- **EFFECTS** = Visualisierungs-Fenster: `currentEffect`, `currentEffectType` (Registry-Name), `currentEffectTitle`, `currentPreset`, `currentPresetTitle`, `currentEffectPresetCount`, `effectCount`, `fullScreen`, `windowed`, `allowAll`; Methoden `next`, `previous`, `nextPreset`, `nextEffect`, `previousEffect`, `effectTitle`, `effectType`, `settings()`. Predefined `WMPEFFECTS`. **[VERIFIED]** ([EFFECTS Element](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/effects-element))
- **VIDEO** = Video-Fenster: `maintainAspectRatio`, `shrinkToFit`, `stretchToFit`, `zoom`, `windowless`, `fullScreen`, `toolTip`; Events `onvideostart`, `onvideoend`. Predefined `WMPVIDEO`. Wichtig (Doku): **ohne VIDEO-Element kehrt WMP bei Videoinhalt automatisch in den Full Mode zurück** (Skin wird verlassen). **[VERIFIED]** ([VIDEO Element](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/video-element))

Headspace: `<effects id="visEffects" visible="false" width=216 height=158>` (Stirnbereich, z. B. Spikes) und `<video id="vid" visible="false" … OnVideoStart="StartVideo();" OnVideoEnd="EndVideo();">` — die beiden schalten sich gegenseitig, je nachdem ob Video läuft. `mediacenter.effectType/effectPreset` werden kopiert (siehe 1.11).

### 1.11 Skripting-Schicht (Events, Listener, Tooltips, Objektmodell)

- **`scriptFile`** lädt zusätzliche JScript-Dateien (semicolon-separiert); `skinname.js` (gleicher Basisname wie `.wms`) wird **automatisch** geladen, auch ohne Angabe. **[VERIFIED]**
- **Event-Handler** als Attribute: `onLoad`/`onClose` (VIEW), `onClick`, `onDblClick`, `onMouseOver/-Out/-Move/-Down/-Up`, `onDragBegin/onDragEnd/onPositionChange` (Slider), `onEndMove` (nach `moveTo`), `onEndAlphaBlend`, `onVideoStart/End`, `onTimer` (VIEW, `timerInterval`), dazu generisch `<attribut>_onchange` (z. B. `value_onchange`). Handler-Argument: globales `event`-Objekt (Maus/Tastatur-Zustand). **[VERIFIED]** ([Ambient Event Handlers](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/ambient-event-handlers), [attribute_onchange](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/attribute-onchange))
- **`jscript:`-Präfix**: Attributwerte/Ausdrücke wie `onClick="jscript:myeffects.next();"` oder `left="jscript:balance.left+balance.width+10;"` — d. h. **Layout kann zur Laufzeit aus anderen Elementen berechnet** werden (Headspace positioniert so Volume- und EQ-Slider relativ zueinander!). **[VERIFIED]** (Beispiele in [mappingColor](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/buttonelement-mappingcolor), [attribute_onchange](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/attribute-onchange))
- **Listening-Attribute** („value changes when source changes“):
  - `wmpprop:GLOBALE.PROPERTY` — bindet **Properties** live (z. B. `value="wmpprop:player.controls.currentPosition"`). **Nicht** auf Methoden verwenden!
  - `wmpenabled:player.controls.PLAY()` — bindet den **enabled**-Status an die Verfügbarkeit einer Controls-**Methode** (z. B. `enabled="wmpenabled:player.controls.play"`; Headspace nutzt dasselbe auf `visible` und `tabStop`). `wmpdisabled:` ist das Gegenstück.
  - Ein `wmponchange:`-Präfix existiert in der Doku **nicht** (Negativbefund) — Re-Binding passiert über `wmpprop` oder `_onchange`-Handler. **[UNCERTAIN, vermutlich Verwechslung]**
  **[VERIFIED]** ([Listening Attributes](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/listening-attributes), [Internal Events](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/internal-events))
- **Tooltip-Mechanik:** Tooltips sind reine Attribut-Texte (`upToolTip`/`downToolTip` an Buttons/Elementen; `toolTip` an Slider/Text/Video), erscheinen beim Hover und sind zur Laufzeit änderbar — Headspace nutzt versteckte Text-Elemente als Speicher und tauscht `upToolTip` beim Öffnen/Schließen der Ohr-Schubladen. **[VERIFIED]**
- **Objektmodell (Global Attributes):** `player` (= Player-Objekt des WMP-Controls), `view` (aktuelles VIEW), `theme`, `event`, `playerApplication` (nur Remote-Hosting). Der Player ist derselbe COM-Objektbaum wie das ActiveX-Control; für Skins zugänglich u. a.: `player.controls.*` (play/pause/stop/next/previous, `currentPosition`, `currentPositionString`, `isAvailable`), `player.settings.*` (volume, balance, mute, …), `player.currentMedia.*` (`name`, `duration`, `durationString`, `imageSourceWidth/Height`, Metadata), `player.network.*` (`downloadProgress`, `bufferingProgress`, `receptionQuality`, …), `player.openState`/`playState`/`status`, `player.playlistCollection` etc. (Felder ohne Stern in [Player Object](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/wmp/player-object) sind skin-tauglich). **[VERIFIED]**
- **`mediacenter` (Headspace!)** — `Init()` liest `mediacenter.effectType` / `mediacenter.effectPreset`, `OnClose()` schreibt sie aus dem Skin zurück. Das Objekt ist in der erhaltenen Referenz **nicht dokumentiert** (weder im TOC der Skin-Referenz noch in „Global Attributes“/„New for WMP Skins“). Beobachtete Semantik: **Persistenz/Synchronisation der Visualisierungs-Auswahl zwischen Skin und Player-Full-Mode** (skin-übergreifende Viz-Einstellung). Namensherkunft („Media Center“ Full-Mode-Terminologie der WMP7-Ära) nicht belegbar. **[UNCERTAIN]** — im Port ersetzbar durch „Viz-Auswahl in VLC-Config merken“.
- **`eq.*`** = Script-Fassade des EQUALIZERSETTINGS (siehe 1.8). **`visEffects.*`** = alles, was das EFFECTS-Element anbietet (`currentPreset`, `currentEffectType`, `next()`, `previous()`, `currentPresetTitle`, …). **[VERIFIED]**

## 6. Relevanz für unseren VLC-Port (die wichtigsten Mapping-Erkenntnisse)

1. **`wmpenabled:`/`wmpdisabled:` = zentrale Interaktions-Semantik.** Buttons (play/pause/prev/next) und Slider waren im Original **zustandsgebunden** (enabled/visible je nach Media-Zustand). In VLC/skins2 gibt es kein direktes „enabled-Listening“ — wir brauchen ein eigenes Mapping pro Control-Zustand (verfügbar/nicht) und müssen entscheiden, welche Zustände wir dynamisch nachbilden. (Vgl. headspace: `visible="wmpenabled:player.controls.pause"`.)
2. **Farb-Mapping (`mappingImage`+`mappingColor`) hat ein VLC-Äquivalent nur als „ein Bitmap pro Button“.** skins2-Buttons brauchen explizite Rechtecke/Bitmaps je Zustand; die freien Klickformen des Originals müssen wir beim Asset-Build **vorzerlegen** (Regionen aus den Map-BMPs in Einzelbuttons umrechnen). Das Mapping-Denkmodell (Bild = Hit-Test) ist damit sehr gut 1:1 automatisiert.
3. **Zwei Transparenzarten getrennt behandeln:** `transparencyColor` (Farbkey **im Bild**) vs. `clippingColor` (Maske für **Form + Nicht-Klickbarkeit**). Für VLC: beides beim Build in **Alpha** (PNG) umrechnen; Formmasken liefern die Fenster-/Subview-Silhouette (Kopfform!). Der Doku-„SUBVIEW-in-SUBVIEW verboten“-Widerspruch betrifft uns nicht, unser Layout ist ohnehin flach.
4. **Bewegung/Animation (`moveTo`+`onEndMove`, `view.width`-Resize, `visible`-Toggles)** treffen die Ohr-Schubladen und den Viz-Schacht. Für skins2 ist das die kritischste Machbarkeitsfrage: Sliding-Trays brauchen **Skript- oder Layout-Animationen** (VLC-`.vlt` kann Positionen animieren — im VLC-Teilbericht zu prüfen), sonst Fallback: härtere Umschaltung/Sofortposition ohne Tween.
5. **Seekbar = Doppel-Fortschritt:** `value` (Position) + `foregroundProgress` (Download/Load-Progress, 0–100 %; Thumb war im Original auf den geladenen Bereich beschränkt). VLC: Seek existiert, „zweiter Balken/Hintergrund“ und ein „nur geladenen Bereich seeken“ gibt es nicht 1:1 — entscheiden: Buffering-Prozent als Deko-Balken oder weglassen (dies ist ein Feature, das im Port sichtbar fehlen wird).
6. **EQ:** 10 Sliders auf `eq.gainLevel1..10` (Band 1 = 31 Hz, ±14 dB im Skin, API ±20 dB), `reset()`, dazu `value_onchange`-Zweiwegebindung. VLC-Core bietet EQ über Audiofilter (10-Band vorhanden?); **skins2-UI-Fähigkeit für EQ-Slider ist die offene Kernfrage** (siehe 00-plan.md Frage 1) — wenn skins2 keinen EQ-Slider exponiert, brauchen wir einen Workaround (z. B. Slider nur als Anzeige + Script/OSC, oder EQ als Nicht-Skin-Panel).
7. **Layout-Rebindings (`jscript:`-Ausdrücke wie `balance.left+width+10`)** und `wmpprop:`-Bindings (`visEffects.currentPresetTitle` → Text) müssen zu **statischem Layout + Slider→Text-Kopplung** werden. Konkret braucht unser Port: Titel-/Preset-Texte, `value_onchange`-Äquivalente (Text/Slider-Aktionen) und einen Ersatz für `mediacenter.effectType/effectPreset` (Viz-Merker in Config) — VLC-Visualisierung ist ohnehin ein Sonderfall.
8. **Tooltips sind Text-Attribute mit Laufzeit-Austausch** (Headspace tauscht „Open…“/„Close…“ je Zustand). VLC-skills2 hat Tooltip-Fähigkeit für Controls — im VLC-Bericht verifizieren und 1:1 übernehmen; die „Return to Full Mode“-Kachel ist semantisch **nicht** abbildbar (kein Full-Mode von uns) → in „Vollansicht/Playlist-Fenster“ bzw. Skin-Ende umdeuten.

## 7. Zusammenfassung (≤300 Wörter)

Die Microsoft-Skin-Doku (WMP7–12) ist noch vollständig online; Headspace nutzt davon exakt: geformte `view`/`subview`-Hüllen (`backgroundColor="none"`, `clippingColor` für Form/Hit-Test, `transparencyColor` als Bild-Farbkey), Farb-Mapping-Buttons (`buttongroup`/`mappingImage`/`mappingColor`, predefined Play/Pause-Elemente), Sliders mit Zweiwegebindung (`wmpprop:`/`value_onchange`) inklusive Doppel-Fortschritt (`useForegroundProgress`/`foregroundProgress` = Download-Progress), `text` mit `cursor`/`onClick`/Tooltip-Tricks, `equalizerSettings` (10 Bänder, `eq.gainLevel1..10`, `reset()`), `playlist` mit `setColumnResizeMode`, `effects`/`video` inkl. Umschaltlogik, dazu JScript-Events (`onLoad`, `onEndMove`, `onDragEnd`, …), `jscript:`-Layoutausdrücke und das Player-Objektmodell (`player.*.player.network.downloadProgress`, `eq.*`, `visEffects.*`). Das `mediacenter`-Objekt (Viz-Persistenz) ist undokumentiert, aber ersetzbar. **`.wmz` ist ein ZIP** — drei unabhängige Belege, lokal bestätigt; kein CAB-Nachweis gefunden. Headspace ist ein **WMP7-Blueskin von 2000** (eines der sieben Startskins, ©2000 Microsoft, Dateidaten Jan–Juni 2000) — nicht Teil einer „WMP9-Media-Center-Suite“, die es so nicht gab; „Media Center XP“ ist ein separater The-Skins-Factory-Skin der XP-MCE-Ära. Tooling damals: Hand-XML + WMP-SDK/Sample-Skins, „WMP 7 Handbook“ (MS Press), TechEd-Talk 2000, Winamp-Skin-Importer im Bonus-Pack 12/2000, später Shareware „WMP SKIN MAKER“; heute reichen 7-Zip + Editor (plus Unblock). Modernes Ökosystem: **nullPlayer** (macOS, GPL-3.0, Clean-Room, sandboxed JScript, WMP7–12, Objektmodell-Whitelist, bündelt keine Skins) ist der einzige Open-Source-`.wmz`-Interpreter; sonst nur Web-Clones/.vlt-Nachbauten. Auf Windows 11 läuft Skin Mode bis zur offiziellen Abschaltung am **10.11.2026** (24H2/25H2/26H2, Win10 ausgenommen); Testausfälle sind meist Workflow/Blocking-Ursachen. Lizenz: ©2000 Microsoft auf allen Assets; Archive/Mirrors und nullPlayer verwalten das als Toleranz-/Link-Modell — kein Freibrief. Fürs VLC-Mapping am wichtigsten: Enabled-Listening, Button-Mapping in Einzelsprites, Alpha statt Farbkeys, Tray-Animation, Doppel-Fortschritt, EQ-UI, Tooltip-Austausch.
